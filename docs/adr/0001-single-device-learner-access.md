# ADR 0001: Одноустройственный доступ ученика (итерация 1.3)

Статус: принято (июль–август 2026)

## Контекст

Письмо-ссылка на доступ раньше открывала learner-кабинет на любом количестве устройств и браузеров: один и тот же access token активировал неограниченные серверные сессии. Это не соответствовало продуктовому требованию «один ученик — одно активное устройство», а повторная отправка одного токена не давала владельцу курса способа перенести доступ при смене устройства.

## Решение

1. **Доступ привязан к устройству.** Первое открытие ссылки `/app/#access=<token>` создаёт в IndexedDB (`lms-device`, запись `main`) неэкспортируемый ECDSA P-256 ключ и `installation_id` (UUID). Backend выписывает challenge, ученик подписывает его, сервер сохраняет устройство и серверную learner-сессию.
2. **Перенос доступа.** Повторная активация по той же ссылке с другого устройства возвращает `409 DEVICE_TRANSFER_CONFIRMATION_REQUIRED`. После подтверждения пользователем access pass ротируется (`generation += 1`), сессии старого устройства аннулируются (`SESSION_REPLACED`), фронтенд показывает «Сессия завершена» и выходит.
3. **Восстановление доступа.** Кнопка в форме входа отправляет запрос с email ученика; письмо содержит одноразовую ссылку `/app/#recovery=<token>`. Подпись запроса: `device.sign("lms-recovery:<installation_id>:<sha256(токен)>")`. Обмен создаёт новый access pass (старый аннулируется) и сразу активирует текущее устройство.
4. **Fragment-ссылки.** `#access=` / `#recovery=` передают токены без попадания в серверные access logs; приложение читает фрагмент (включая `hashchange`, когда ссылку открывают в уже открытом кабинете) и удаляет его через `replaceState`. Legacy-путь `/app/access/<token>` продолжает приниматься.
5. **Endpoint-ы `/api/v1/auth/*`** (inspect, exchange, me, heartbeat, logout, recovery/request, recovery/exchange) отделены от контентных learner-API. CSRF token ротируется после каждого успешного exchange/recovery.
6. **Консистентность транзакций.** Все `select_for_update` выполняются внутри `transaction.atomic`; повторный `login()` на занятом session key переключает ключ сессии (`cycle_key`).
7. **Heartbeat** каждые 10 секунд синхронизирует состояние: `401 SESSION_REPLACED/REVOKED/EXPIRED` завершает сессию на фронтенде и очищает офлайн-пакеты.

## Последствия

- В БД хранится только HMAC-хеш access token (`token_hash`) и fingerprint публичного ключа устройства; raw token и приватный ключ не покидают письмо/браузер.
- Офлайн-license теперь привязана к `access_pass_id` и `pass_generation`: перенос/восстановление инвалидирует старые офлайн-пакеты.
- Письмо при выдаче доступа адресовано доступу в целом («Доступ к курсам: <vendor>»), а не отдельному курсу.
- `PWA_TRANSFER_PEPPER` и модель PWA-session-transfer больше не используются (код удалён).
